# FitnessNote 모바일 웹

React + Vite로 만든 프론트엔드입니다. 백엔드와 별도 터미널에서 실행합니다. 설치형 앱이나 외부 배포는 하지 않습니다.

## 실행

현재 프로젝트의 `backend`와 같은 위치에 이 `frontend` 폴더를 둡니다.

```text
FitnessNote/
  backend/
  frontend/
```

첫 번째 터미널에서는 기존 FastAPI 서버를 계속 실행합니다.

```bash
cd backend
source .venv/bin/activate
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

두 번째 터미널에서는 프론트엔드를 실행합니다. Node.js 22 권장.

```bash
cd frontend
npm install
npm run dev
```

브라우저에서 http://localhost:5173 을 엽니다. Postman에서 가입한 계정으로 로그인할 수 있습니다. 로그인 토큰은 현재 탭의 sessionStorage에 보관되며 만료 시 로그인 화면으로 돌아갑니다. DB 비밀번호는 프론트엔드에 입력하지 않습니다.

프론트 요청은 `/api` 경로로 보내고 Vite가 `http://127.0.0.1:8000`으로 전달합니다. 따라서 휴대폰도 Vite를 통해 같은 백엔드에 접속하며 CORS 설정이나 백엔드의 외부 노출을 변경할 필요가 없습니다. 백엔드 주소를 바꾸려면 `.env.example`을 `.env`로 복사하고 `BACKEND_URL`을 변경한 후 Vite를 재시작하세요.

## 휴대폰에서 보기

컴퓨터와 휴대폰을 같은 Wi-Fi에 연결합니다. `npm run dev`가 출력하는 `Network: http://컴퓨터IP:5173/` 주소를 휴대폰 브라우저에서 엽니다. macOS 방화벽이나 공유기의 기기 간 접근 차단 설정에 따라 접근 허용이 필요할 수 있습니다. PC의 `localhost` 주소를 휴대폰에 입력하면 PC에 연결되지 않습니다. 로컬 Wi-Fi 테스트용이며 외부 인터넷에 공개하지 않습니다.

## 구현한 화면

- 로그인·회원가입, 로그아웃 및 로그인 만료 처리
- 로그인 직후 한국 시각 오늘의 일지
- 월~일 주간 줄: 기록이 있는 날짜는 색칠, 선택 날짜는 테두리, 오늘은 작은 점
- 달력: 월 이동·기록 날짜 표시·날짜 선택·오늘로 이동
- 빈 일지와 운동 추가 버튼
- 운동 검색, 공용·개인 구분, 개인 운동 생성
- 세트 추가·입력·삭제, 종목별 전체 세트 저장, 기존 기록 수정·종목 삭제
- 이전 기록: 선택일 이전 **최근 1년 내** 가장 최근 동일 종목의 전체 세트. 그보다 오래된 기록 검색은 후속 전용 API로 확장할 예정입니다.
- 운동 보관함: 전체·공용·개인 필터, 비활성 상태 표시, 새 운동 등록
- 통계: 최근 30일·90일·1년, 종목 선택, 최고 중량 / 총 반복 수 / 두 지표 함께 중 하나만 선택, 그래프 하나와 선택 지표의 수치 표
- 관리자 로그인: 피드백 대기·완료 목록, 요청 검토·답변 작성·수정, 사용자 검색, 전체 일지·종목별 변화 조회, 공용 운동 목록·등록 화면.

통계는 현재 백엔드의 날짜 목록·일지 API를 조합해 계산합니다. 기록이 많아지면 서버에서 집계하는 전용 API로 바꾸는 편이 좋습니다. 운동이 없는 날짜를 0으로 집계하지 않습니다. 맨몸 운동은 총 반복 수로 비교할 수 있습니다.

피드백이 있는 일지는 읽기 전용으로 표시합니다. 운동을 하나 이상 저장하면 피드백 신청 버튼을 제공합니다. 대기 중에는 신청을 취소해 편집을 다시 허용할 수 있고, 완료 후에는 답변을 확인합니다. 비활성 운동도 이미 기록된 항목에서는 편집할 수 있습니다. 운동 삭제는 종목 정의가 아닌 그날의 기록 삭제입니다.

## 검증

```bash
npm test
npm run build
```

이 명령은 날짜 계산·집계·요청 동시 실행 제한과 프로덕션 번들을 확인합니다. 실제 MySQL 저장은 실행한 백엔드로 별도 확인해야 합니다. 최종 정적 번들만 단독으로 열면 API 프록시가 없으므로 사용할 수 없습니다. 로컬 미리보기는 `npm run preview`로 실행하면 API 프록시가 유지됩니다.

공식 참고: [Vite 프록시](https://vite.dev/config/server-options#server-proxy), [React 데이터 조회 효과 정리](https://react.dev/learn/synchronizing-with-effects).

## 화면 수정 사항

주간 날짜 아래의 설명·일수 문구와 하루 요약 칸을 제거했습니다. 각 운동 카드에는 세트별 기록과 큰 기록 수정 버튼을 표시하며 세트 수·총량 요약과 구분선을 제거했습니다. 통계는 네모 모양의 라디오 버튼으로 하나만 선택합니다. 함께 보기는 그래프 하나에 중량(왼쪽 kg)과 반복 수(오른쪽 회)를 서로 다른 색·선 모양으로 표시합니다. 루틴 기능은 이번 범위에서 제외하며 DB와 백엔드는 변경하지 않습니다.

## 관리자·피드백 사용 순서

1. backend 터미널에서 `python create_admin.py`로 관리자 계정을 한 번 생성합니다. 일반 회원가입은 항상 USER 계정입니다. 기존 아이디와 겹치지 않게 만드세요.
2. 사용자로 로그인해 운동을 저장한 뒤 일지 하단 “피드백 신청”을 누릅니다. 질문은 선택 입력이며, 신청 전에 편집 잠금 안내를 확인할 수 있습니다.
3. 로그아웃 후 관리자 계정으로 로그인하면 별도의 관리자 화면이 열립니다.
4. “피드백 관리 → 답변 대기”에서 요청을 선택합니다. 신청한 일지뿐 아니라 해당 사용자의 모든 과거 일지도 날짜 목록과 페이지 이동으로 조회합니다. 종목별 변화는 선택 날짜를 기준으로 최근 30일·90일·1년 중 선택합니다. 더 오래된 시점도 그 날짜 일지를 선택해 조회할 수 있습니다.
5. 답변을 등록하면 완료 목록으로 이동합니다. 작성한 관리자만 답변 내용을 수정할 수 있고, 다른 관리자는 읽기만 가능합니다.
6. 사용자로 다시 로그인하면 일지 하단에서 완료된 답변을 확인합니다. 완료 일지의 기록 수정·운동 추가 버튼은 숨겨지며 서버도 변경을 거절합니다.

관리자의 “사용자 기록” 메뉴는 요청 여부와 무관하게 모든 일반 사용자를 검색하고 기록·통계를 조회합니다. 계정 변경·삭제나 사용자 기록 변경 기능은 제공하지 않습니다. 사용자 화면은 모바일 우선, 관리자 화면은 PC 우선이며 작은 화면에서도 메뉴와 검토 내용을 사용할 수 있습니다. 새로운 패키지 설치나 DB SQL 재실행은 필요하지 않습니다.
